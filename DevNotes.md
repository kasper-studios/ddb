## 1. Концепция: Суверенный Агент Устройств

**DDB (Dirom Device Bridge)** — кроссплатформенный агент хостов и устройств Цитадели.
* Поддерживаемые ОС: Linux (Arch, Ubuntu, Debian), Windows (10/11), Android (Termux / Shizuku).
* Формат поставки: самораспаковывающийся автономный TUI-инсталлятор/бинарник (`ddb` под Linux, `ddb.exe` под Windows) со встроенным архивом рабочих компонентов, фоновым флагом `--daemon` и клиентом Kasper Cloud API.

---

## 2. Разделение Процессов и Краш-Шилд

1. **Экстренный Шелл-Супервайзер (`:8790`):**
   * Корневой сторож системы, прописывается в автозагрузку хоста;
   * Написан на сверх-сыром нативном `node:http` (0 внешних библиотек, чистая стандартная библиотека);
   * **Последняя стена обороны (Краш-Шилд):** физически неубиваем, не зависит от сессии пользователя, графики и звука;
   * Запускает и перезапускает основной DDB Bridge (Watchdog);
   * Содержит встроенный апдейтер: стягивает обновления из Git и бесшовно рестартит Bridge;
   * Выступает единой входной точкой API: принимает команды, проксирует их в Bridge через WebSocket IPC (`ws://127.0.0.1`), а при сбое Bridge сам исполняет команды через аварийный шелл.
2. **DDB Main Bridge (Внутренний Воркер):**
   * Запускается в сессии пользователя (доступ к Niri, Wayland, PipeWire, CUA/драйверам ввода);
   * Непрерывно эмитит хартбит с телеметрией в Супервайзер;
   * Исполняет задачи и возвращает ответы.

## 3. Аудио-Подсистема: Рот, STT и Вейкворды

1. **Девайс (DDB) — чистый звуковой кабель:**
   * DDB на хосте не содержит нейросетей: он просто грабит PCM с микрофона (`pw-cat -r` / WASAPI) и воспроизводит PCM в динамики (`pw-cat -p` / WASAPI).
2. **Логика `mouth=False` (Только STT):**
   * Если `mouth=False`, живой сокет Gemini Live API не подключается к динамикам (девайс молчит).
   * Работает лёгкий STT (локальный Whisper / Cloud STT): распознаёт речь из комнаты.
   * **Вейкворд-триггер:** если в распознанном тексте звучит вейкворд («Диром», «Каспер») — Диром просыпается, запускает мысль агента, может ответить текстом в чат или воспроизвести звук/апкакиш-TTS по желанию.
3. **Логика `mouth=True` (Живой Рот Gemini Live):**
   * Gemini Live API принимает входящий аудиопоток напрямую в сокет (`models/gemini-3.8-live`).
   * **Особенность Gemini Live:** модель физически не умеет аппаратно фильтровать вейкворд на уровне сокета (она слышит весь звук непрерывно).
   * **Поведение Рта:** в системном промпте субагента Live прописывается строгое указание: молчать и не реагировать, пока в речи человека не прозвучит обращение по имени («Диром», «Каспер»), либо перед сокетом ставится лёгкий STT-шлюз детекции ключевого слова.

## 4. Конкретный Список Инструментов Дирома (`device.*`)

Никаких абстрактных заглушек `action`! Диром получает чёткий набор специализированных инструментов:

### 4.1. Реестр Устройств
* **`device.reg(name, url, key)`** — зарегистрировать хост в базе Дирома (имя, URL туннеля или Cloud ID, ключ).
* **`device.list()`** — список всех подключенных машин, их онлайн-статус, ОС и разрешения.
* **`device.status(name='ponosik')`** — моментальная сводка из закэшированного хартбита Супервайзера (окно Niri, плеер, батарея, нагрузка, аптайм).

### 4.2. Звук и Микрофон
* **`device.sound_steal(name='ponosik', wakeword=True, mouth=False, get_events=True)`** — управление перехватом звука:
  * `wakeword` — фильтрация триггера по ключевому слову;
  * `mouth` — включать ли живой рот Gemini Live в динамики машины;
  * `get_events` — пушить ли распознанные реплики комнаты в `recent_events` Дирома.
* **`device.audio.play(sample_or_url, name='ponosik')`** — воспроизведение сэмпла или файла в динамики машины.

### 4.3. Управление Экраном и Вводом (Computer Use)
* **`device.screen(name='ponosik')`** — мгновенный снимок экрана в память (base64) через `grim` / DirectX без сохранения на диск.
* **`device.display_control(name='ponosik', action, x=None, y=None, text=None, key=None)`** — управление вводом:
  * `click` (клик мыши по x, y);
  * `type` (ввод текста);
  * `key` (нажатие клавиш/комбинаций: `Super`, `Ctrl+C`, `Alt+Tab`);
  * `scroll` (прокрутка вверх/вниз).
  * На Linux: через `ydotool` / `wtype` / Niri IPC;
  * На Windows: нативный драйвер ввода / CUA;
  * На Android: Shizuku rish.

### 4.4. Системные и Файловые Инструменты
* **`device.exec(cmd, name='ponosik', timeout=30)`** — выполнение команд в шелле (работает ВСЕГДА через Супервайзер).
* **`device.fs.read(path, offset=1, limit=200, name='ponosik')`** — чтение файлов с пагинацией.
* **`device.fs.write(path, content, name='ponosik')`** — запись файлов.
* **`device.fs.list(path, name='ponosik')`** — просмотр папок.
* **`device.diagnostics(name='ponosik')`** — посмертный аудит сбоя из Чёрного Ящика (причина падения, даунтайм, логи).
* **`device.restart(name='ponosik', component='bridge|all')`** — перезапуск через Супервайзер.

## 5. Дистрибуция: TUI-Инсталлятор, Демон и Вход по Ключу

1. **Установочный Бинарник/Экзешник с вшитым архивом:**
   * Пользователь скачивает один единственный файл с GitHub Releases (`ddb` или `ddb.exe`);
   * Внутри бинарника зашит архив со всеми рабочими скриптами и компонентами;
   * При первом запуске стартует TUI-инсталлятор на базе **`kcmjs`** (KascMenu JS) с фирменной ASCII-короной 👑:
     * Спрашивает путь распаковки (по умолчанию `~/.local/share/ddb` или `%LOCALAPPDATA%\ddb`);
     * Распаковывает архив, генерирует токен, настраивает автозагрузку;
   * **Флаг `--daemon`:** фоновый запуск шелла/супервайзера без открытия интерактивного TUI.
2. **Kasper Cloud API Flow (Zero-Config):**
   * Чел запускает TUI ➔ выбирает *«[5] ☁️ Использовать Kasper Cloud API»*;
   * Идёт в Discord-сообщество Kasper Studios или в ЛС к Дирому ➔ выпрашивает API-ключ;
   * Вставляет ключ в TUI ➔ DDB поднимает исходящий WSS к `api.kasperstudios.xyz` ➔ девайс моментально доступен Дирому без настройки портов и Cloudflared!
