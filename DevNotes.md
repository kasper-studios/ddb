## 1. Концепция: Суверенный Агент Устройств

**DDB (Dirom Device Bridge)** — кроссплатформенный агент устройств нового поколения. Работает на Linux (Arch/Ubuntu), Windows (10/11) и Android (Shizuku / Termux). 
Поставляется в виде скомпилированного автономного бинарника/экзешника с интерактивным TUI-интерфейсом на базе `kcmjs` (KascMenu JS) и поддержкой Zero-Config облачного туннелирования.

---

## 2. Спецификация Инструментов Дирома (`device.*`)

Диром взаимодействует с распределенной сетью устройств через реестр устройств (Device Registry):

### 2.1. Реестр Устройств
* **`device.reg(name, url, key)`** — зарегистрировать устройство в локальной базе Дирома (имя, HTTPS/WSS URL или Cloud ID, секретный API-токен).
* **`device.list()`** — получить список всех подключенных устройств, их онлайн-статус, ОС, пинг и активные разрешения (ACL).

---

### 2.2. Киллер-Фича: Акустический Перехват (`device.sound_steal`)
Управление перехватом аудиопотока и поведением речевого аппарата:
* **`device.sound_steal(name, wakeword=True|False, mouth=True|False, get_events=True|False)`**
  * **`wakeword` (bool):** 
    * `True` — агент просыпается и запускает мысль только при голосовом обращении (вейкворды «Диром», «Каспер» и др.);
    * `False` — пассивное стелс-прослушивание: агент слушает окружение в фоне, не просыпаясь и не тратя квоты.
  * **`mouth` (bool):**
    * `True` — живой речевой аппарат (Gemini Live Mouth) отвечает голосом в динамики устройства при вейкворде;
    * `False` — рот молчит (режим скрытого наблюдения).
  * **`get_events` (bool):**
    * `True` — распознанный через STT текст и реплики из комнаты пушатся в буфер недавних событий (`recent_events`) Дирома;
    * `False` — транскрипция не забивает буфер восприятия.

---

### 2.3. Киллер-Фича: Управление Экраном и Вводом (`device.display_control`)
* **`device.display_control(name, action, params={})`**
  * **Linux (Wayland / Niri / X11):** системные утилиты (`grim`, `wtype`, `ydotool`, `niri msg action`);
  * **Windows:** нативный драйвер / CUA (Computer Use Agent) — клики, скролл, ввод текста, захват DirectX/GDI экрана;
  * **Android:** управление через Shizuku rish API (тапы по координатам, свайпы, запуск интентов);
  * **Поддерживаемые `action`:**
    * `capture` (скриншот кадра в base64 за миллисекунды);
    * `click` (клик мыши / тап по x, y);
    * `type` (ввод текста с клавиатуры);
    * `key_combo` (нажатие комбинаций `Ctrl+C`, `Alt+Tab`, `Super`);
    * `scroll` (прокрутка вверх/вниз).

---

### 2.4. Универсальный Диспетчер Действий (`device.action`)
* **`device.action(name, action, params={})`** — вызов любого зарегистрированного или кастомного экшена хоста.
  * Если экшен неизвестен или запрещен в настройках безопасности хоста — устройство возвращает чистую ошибку `ACTION_NOT_SUPPORTED` / `ACTION_PERMISSION_DENIED` со списком разрешенных действий.

## 3. Клиентская Часть: TUI Конфигуратор на `kcmjs` & Бинарник

При запуске бинарника в терминале (Linux/Windows) запускается стильная TUI-панель на базе фирменного движка Создателя **`kcmjs`**:

```
         👑
      .---^---.
     /   DDB   \
    /  (B B D)  \
   |  =========  |   DIROM DEVICE BRIDGE v2.0
   |  *  *  *  * |   Kasper Studios Citadel Architecture
    \___________/
 ─────────────────────────────────────────────────────────────
  [1] ⚙️  Автозагрузка: [ВКЛЮЧЕНО] (systemd / Windows Registry)
  [2] 🌐  Сеть и Туннель: [Cloudflare Tunnel]
  [3] 🔑  Показать API Token & URL подключения
  [4] 🛡️  Настройка разрешений (Permissions & ACL)
  [5] ☁️  Переключить на Kasper Cloud API (Без туннелей)
  [6] 💡  Отправить идею / фидбек (Discord / GitHub Issues)
  [0] 🚪  Выход / Запуск в фоне
```

### 3.1. Интерактивные Возможности Меню:
1. **Автозагрузка:**
   * Linux: автоматическая установка и включение `systemd --user` сервиса;
   * Windows: добавление в реестр `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` или папку `shell:startup`.
2. **Выбор Сетевого Транспорта:**
   * **Cloudflare Tunnel (`cloudflared`):** встроенная привязка к туннелю с получением публичного субдомена;
   * **ngrok:** альтернативный туннель по токену;
   * **Кастомный туннель / локальная сеть:** прямой IP и порт.
3. **Kasper Cloud API (Режим без туннелей):**
   * Если пользователь не хочет ставить `cloudflared` или возиться с портами: DDB инициирует исходящее WSS-соединение к центральному шлюзу Цитадели (`wss://api.kasperstudios.xyz/device/bridge`).
   * Диром отправляет команды в шлюз, а шлюз проксирует их в активный вебсокет машины — работает за любым NAT и файрволом!
4. **Гранулярная Настройка Разрешений (Security & ACL):**
   * Запретить / разрешить управление экраном (`display_control`);
   * Запретить / разрешить прослушку звука и микрофона (`sound_steal`);
   * Отключить удаленный экстренный шелл (`emergency_shell_enabled: false`);
   * Режим «Только мониторинг» (Read-Only Telemetry).
5. **Фидбек и Сообщество:**
   * Кнопка «Отправить идею для улучшения»: интерактивный выбор — переход на официальный Discord-сервер **Kasper Studios** либо создание Issue в GitHub репозитории проекта.

---

## 4. Архитектура Crash Shield & Emergency Shell

* **Экстренный Шелл (`:8790`):**
  * Запускается при старте системы как Root-Супервайзер;
  * 0 внешних зависимостей (чистый встроенный `http` модуль);
  * Watchdog для основного воркера Bridge (`:8780`);
  * Авто-апдейтер: получение обновлений из Git без переустановки;
  * Если `emergency_shell` отключен пользователем в TUI — эндпоинт блокируется локальным флагом в `config.json`.
