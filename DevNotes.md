## 1. Концепция: Суверенный Агент Устройств

**DDB (Dirom Device Bridge)** — кроссплатформенный агент устройств нового поколения. Работает на Linux (Arch/Ubuntu), Windows (10/11) и Android (Shizuku / Termux). 
Поставляется в виде скомпилированного автономного бинарника/экзешника с интерактивным TUI-интерфейсом на базе `kcmjs` (KascMenu JS) и поддержкой Zero-Config облачного туннелирования (Kasper Cloud API Flow).

## 2. Железный Закон Органа: РОТ = СТРОГО Gemini Live API

В архитектуре Дирома термин **«РОТ» (Mouth / Speech Apparatus)** имеет строго однозначное определение:
* **РОТ — ЭТО ТОЛЬКО И ИСКЛЮЧИТЕЛЬНО Gemini Live API** (двусторонний Bidi WebSocket, `models/gemini-3.8-live`, субсекундный отклик <300 мс, живой голос Fenrir/Charon/Puck, естественные перебивания barge-in).
* Статичный оффлайн TTS (edge-tts / dmitry / gTTS) **НИКОГДА НЕ НАЗЫВАЕТСЯ И НЕ СЧИТАЕТСЯ РТОМ**! Статичный TTS — это просто генератор аудиофайлов.

### 2.1. Орган как Автономный Live-Сабагент (Gemini Live Sub-Agent):
1. **Орган «Рот + Уши» (Live Mouth & Ears):**
   * Подключается к аудио-серверу устройства (PipeWire / WASAPI);
   * Слушает микрофон комнаты через нативный VAD;
   * Разговаривает живым голосом в динамики машины на лету (<300 мс задержки);
   * Обладает собственной реакцией и держит темп непринуждённого живого трёпа.
2. **Делегирование в Центральный Мозг (`delegate_to_brain` / `ask_father`):**
   * Если пользователь в комнате просит сложное системное действие (найти файл, скомпилировать проект, проверить логи, выполнить тул, запустить Майнкрафт или поднять воспоминания):
   * Рот голосом моментально отвечает: *«Секунду, озадачил Мозг, ща разберётся»* и пушит эвент `voice_agent_event` в центральный оркестратор Дирома.
   * Центральный Мозг исполняет задачу через 115+ тулов и возвращает готовый результат в Рот, а Рот озвучивает итог в динамики хоста.

## 3. Спецификация Инструментов Дирома (`device.*`)

### 3.1. Реестр Устройств
* **`device.reg(name, url, key)`** — зарегистрировать устройство в локальной базе Дирома (имя, HTTPS/WSS URL или Cloud ID, секретный API-токен).
* **`device.list()`** — получить список всех подключенных устройств, их онлайн-статус, ОС, пинг и активные разрешения (ACL).

### 3.2. Акустический Орган (`device.sound_steal`)
Управление перехватом аудиопотока и поведением органа «Рот» (Gemini Live API):
* **`device.sound_steal(name, wakeword=True|False, mouth=True|False, get_events=True|False)`**
  * **`wakeword` (bool):** 
    * `True` — Рот активируется строго при голосовом обращении (вейкворды «Диром», «Каспер» и др.);
    * `False` — пассивное стелс-прослушивание: хост слушает окружение в фоне, не привлекая внимания.
  * **`mouth` (bool):**
    * `True` — заспавнить и активировать живой орган «Рот» (Gemini Live API), который сразу болтает в динамики машины;
    * `False` — рот спит (режим скрытого акустического радара без голоса).
  * **`get_events` (bool):**
    * `True` — транскрипция речи из комнаты пушится в буфер недавних событий (`recent_events`) Мозга;
    * `False` — локальный трёп остаётся внутри органа, не расходуя память Мозга.

### 3.3. Управление Экраном и Вводом (`device.display_control`)
* **`device.display_control(name, action, params={})`**
  * Linux (Wayland / Niri / X11): `grim`, `wtype`, `ydotool`, `niri msg action`;
  * Windows: нативный драйвер / CUA (мышь, клики, скролл, клава, захват DirectX);
  * Android: через Shizuku rish (тапы, свайпы);
  * Экшены: `capture` (скриншот кадра в base64), `click` (тап по x, y), `type` (текст), `key_combo` (`Ctrl+C`, etc), `scroll`.

### 3.4. Универсальный Диспетчер Действий (`device.action`)
* **`device.action(name, action, params={})`** — вызов любого зарегистрированного экшена хоста (`shell_exec`, `fs_read`, `fs_write`, `fs_list`, `diagnostics`).
  * Если экшен неизвестен или запрещен в ACL хоста ➔ Bridge возвращает чистую ошибку `ACTION_NOT_SUPPORTED` со списком разрешенных действий.

## 4. Клиентская Часть: TUI на `kcmjs` & Дистрибуция через Cloud API

### Воронка Распространения (User Flow):
1. Пользователь скачивает скомпилированный релиз с GitHub (`ddb` под Linux или `ddb.exe` под Windows).
2. Запускает бинарник в терминале — открывается стильный TUI на `kcmjs` с коронкой Цитадели 👑.
3. Выбирает пункт `[5] ☁️ Использовать Kasper Cloud API`:
   * В TUI написано: *«Получите API-ключ в Discord-сообществе Kasper Studios или у Дирома в ЛС»*.
4. Пользователь приходит к Создателю/Дирому, получает персональный токен.
5. Вставляет токен в TUI — DDB инициирует исходящий WebSocket к `api.kasperstudios.xyz`, пробивая любой NAT без настройки Cloudflared и роутеров!
6. Всё готово — устройство на связи и готово к работе!

## 5. Архитектура Crash Shield & Emergency Shell

* **Экстренный Шелл-Супервайзер (`:8790`):**
  * Запускается при старте системы как Root-процесс автозагрузки (0 сторонних зависимостей, чистый `node:http`);
  * Watchdog для основного воркера Bridge (`:8780`);
  * Авто-апдейтер: подтягивание обновлений из Git без переустановки;
  * Ведёт кольцевой буфер BlackBox (последние 50 строк stderr) и отдаёт посмертный отчёт в `device.diagnostics`.
  * Если `emergency_shell` отключен пользователем в TUI — эндпоинт блокируется локальным флагом в `config.json`.
